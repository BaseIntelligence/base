## Summary

A throwaway Phala TDX CVM was deployed with a measured app-compose that includes:
  1) tecnativa/docker-socket-proxy (digest-pinned) mounting guest /var/run/docker.sock:ro
  2) alpine agent that talks to the proxy over TCP :2375 and runs hello-world via Docker Engine API

Result: nested container hello-world exited 0 inside the CVM. Attestation event log contains
compose-hash matching the deployed compose. Quote embeds 0x01||compose_hash (mr_config_id layout).

CVM torn down after evidence capture (status deleting → gone).

## Caveats (do not over-claim)

1. Runtime-spawned containers (hello-world here) are NOT individually listed in compose-hash/RTMR3.
   Only the measured compose services (socket-proxy + agent) are. Nested image integrity is an
   application-policy problem (digest allowlist inside measured agent), not automatic RTMR coverage.

2. gbase frozen contract AGENT_CHALLENGE.md §9.1 still says:
   "No other long-lived services required for v1. No docker.sock. No `:latest` tags."
   This SPIKE proves Phala/dstack PLATFORM capability. Adopting socket-proxy in the normative
   miner template requires an explicit contract/measurement allowlist change — out of scope here.

3. OS image used: dstack-dev-0.5.9 (is_dev=true) — still real TDX CVM on Phala Cloud node prod5
   (US-WEST-1). Instance type tdx.small (1 vCPU / 2GB).

4. Nested hello-world used tag :latest for the spike only; production must digest-pin.
